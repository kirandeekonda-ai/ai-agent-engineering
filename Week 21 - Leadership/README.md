## 📚 Part 1: Technical Communication

### Writing Skills

| Document Type | Purpose | Tips |
|--------------|---------|------|
| **RFC/Design Doc** | Propose architecture changes | Problem → Solution → Trade-offs |
| **ADR** | Record decisions | Context → Decision → Consequences |
| **Technical Blog** | Share knowledge | Clear, visual, actionable |
| **Runbook** | Operations guide | Step-by-step, tested |

**RFC Template:**
```markdown
# RFC: [Title]

## Problem
What problem are we solving?

## Proposal
What is the solution?

## Alternatives Considered
What else did we evaluate?

## Trade-offs
What are we gaining/losing?

## Timeline
When will this be done?
```

### Presentation Skills

| Audience | Focus On |
|----------|----------|
| **Engineers** | Technical depth, code examples |
| **Managers** | Progress, blockers, timeline |
| **Executives** | Business impact, ROI, risks |

**Executive Communication Formula:**
```
1. Bottom Line Up Front (BLUF)
2. 3 key points
3. Clear ask/recommendation
```

## 📚 Part 2: Leadership Skills

### Influence Without Authority

| Method | How |
|--------|-----|
| **Build Trust** | Deliver consistently, be reliable |
| **Show Data** | Back opinions with evidence |
| **Listen First** | Understand before proposing |
| **Give Credit** | Acknowledge others' contributions |

### Mentoring Framework

```
1. Diagnose: What does the mentee need?
   - Technical skills gap
   - Career guidance
   - Problem-solving approach

2. Guide: Don't give answers, ask questions
   - "What have you tried?"
   - "What would happen if...?"
   - "What are the trade-offs?"

3. Review: Provide actionable feedback
   - Specific, not vague
   - Timely, not delayed
   - Balanced (positive + constructive)
```

### Cross-Functional Collaboration

| Team | How to Work With Them |
|------|----------------------|
| **Product** | Understand the "why", propose the "how" |
| **Design** | Technical constraints, feasibility |
| **Data Science** | Model requirements, integration |
| **Security** | Early involvement, compliance |

## 📚 Part 3: Business & Strategy

### ROI Analysis for AI Projects

```
ROI = (Benefit - Cost) / Cost × 100%

Example: AI Chatbot
- Cost: $50K (development) + $10K/year (operations)
- Benefit: 3 support agents × $60K = $180K/year saved
- ROI: ($180K - $60K) / $60K = 200% Year 1
```

### Build vs Buy Decision

| Factor | Build | Buy (API) |
|--------|-------|-----------|
| **Time** | Months | Days |
| **Cost** | High upfront, low ongoing | Low upfront, ongoing fees |
| **Control** | Full customization | Limited |
| **Maintenance** | You own it | Provider handles |
| **When to Choose** | Core differentiator | Commodity feature |

### AI Governance & Ethics

| Principle | How to Implement |
|-----------|-----------------|
| **Fairness** | Test for bias across groups |
| **Transparency** | Explain AI decisions to users |
| **Privacy** | Minimize data collection, PII protection |
| **Accountability** | Human oversight, audit trails |

**Compliance Frameworks:**
| Framework | Focus |
|-----------|-------|
| GDPR | EU data privacy |
| CCPA | California privacy |
| SOC 2 | Security controls |
| HIPAA | Healthcare data |

## 🎤 Interview Questions

### Leadership
1. Tell me about a time you influenced a decision without authority
2. How do you handle disagreements with senior engineers?
3. Describe how you mentored someone

### Business
1. How do you prioritize between technical debt and features?
2. How would you justify an AI project to executives?
3. What's your approach to build vs buy decisions?

### Ethics
1. How do you ensure AI fairness?
2. What would you do if asked to build something unethical?
3. How do you handle user data privacy?

```
Senior Engineer:
  "I solved the problem"

  "I influenced the organization's direction"
```
